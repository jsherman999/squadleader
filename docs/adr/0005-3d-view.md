# 0005: The 3D view

**Status:** Accepted

## Decision

The 3D landscape (`apps/web/src/scene3d`) is plain, imperative three.js behind a small class, `Scene3D`, with the same pointer API as the 2D `BoardRenderer`. It is not built with react-three-fiber.

- **One source of geometry.** The 3D scene is built from the same `GameMap` and `mapGeometry` as the 2D board: building footprints, woods outlines, road chains and hexside features. Nothing is modelled by hand, so a board edited in the editor shows up in 3D unchanged.
- **Heights follow the LOS model.** A level is `LEVEL` world units. A small building's ridge, a multi-story building's ridge and an average tree top sit at the obstacle heights of ADR 0004 (tested in `heights.test.ts`). An exaggeration slider scales the whole scene vertically; it changes the look, not the rules.
- **The rules decide visibility.** 3D is a picture of the rules' categorical LOS, not a second LOS engine. The LOS ray runs between the eye heights `bestLos` reports and stops at the obstacle the rules name. In POV, enemy units are hidden unless the rules give LOS to their hex, even when the geometry shows a sliver of them.
- **Overlays are drawn once, for both views.** Overlay code draws to a `Pen` (polygon, line, circle, text in map units). `pixiPen` draws it on the 2D board; `canvasPen` draws it on a canvas that is draped over the terrain as a second texture, with text turned into 3D sprite labels. Selections, paths, objectives, danger shading, viewsheds and fire lines therefore look the same in both views.
- **The ground is a painted texture.** Meadow, fields, yards, woods floor, roads, craters and a faint hex grid are painted on one canvas, rather than modelled. Buildings are extruded footprints with hip roofs; trees, hedges, walls and chimneys are instanced.
- **Views stay mounted.** `MapViews` mounts the 2D and 3D views the first time each is shown and keeps them, hidden, so switching is instant. A hidden 3D view skips rendering.

## Why

- react-three-fiber would add a reconciler and a second component model for a scene that changes in a few coarse steps (map, units, overlay), which imperative code handles simply.
- Building 3D from the board data means the two views can't drift apart, and new boards cost nothing extra.
- A draped overlay texture is cheaper and simpler than placing ground-hugging decals on uneven terrain, and it lets overlay code be shared with 2D.

## Costs

- Draped overlays are limited by the overlay texture's resolution (32 pixels per map unit, up to 2048 px). Fine lines blur when the camera is very close.
- Units are flat counter standees for now; miniatures are a later option (§7.4 of the plan).
- POV from inside a building hides that building, which is simpler than modelling interiors and window openings.
